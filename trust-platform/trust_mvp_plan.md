# خطة تنفيذ منصة TRUST — المدير التجاري الذكي (MVP)

**الإصدار:** v0.1
**التاريخ:** 2 يوليو 2026
**النطاق:** مرحلة أولى (Rule-Based، بدون شات بوت / بدون ذكاء اصطناعي)

---

## 1. نظرة عامة

TRUST منصة ذكاء أعمال تعطي المؤسسات التجارية (سوبرماركت، صيدلية، شركة، مطعم... إلخ) رؤية موحّدة عن المبيعات والمخزون والسيولة والربحية، وتترجمها إلى توصيات تنفيذية قابلة للتطبيق. المرحلة الأولى قائمة كليًا على قواعد محددة مسبقًا (Rules Engine)، والبيانات الأساسية (المبيعات، الربح، السيولة) يدخلها المستخدم يدويًا عبر الموقع.

**الأطراف في النظام:**
- **مستخدم مؤسسة (Tenant)**: له فرع واحد أو أكثر، تصنيف نشاط تجاري واحد، ومستخدمين (أدوار) يديرون بياناته.
- **الأدمن (منصة TRUST)**: يشرف على كل المؤسسات، ويشغّل طبقتي الشراء الجماعي وتصريف الراكد بين الزبائن.

## 2. نموذج البيانات الأساسي

### 2.1 Organization (المؤسسة)
| الحقل | الوصف |
|---|---|
| id | معرف فريد |
| name | اسم المؤسسة |
| category | تصنيف النشاط: `SUPERMARKET`, `PHARMACY`, `RESTAURANT`, `RETAIL_CLOTHING`, `GENERAL_TRADE`, `COMPANY_OTHER` |
| createdAt | تاريخ الإنشاء |

التصنيف مهم لأنه يحدد **معايير المقارنة (Benchmarks)** المستخدمة في حساب السكور (هامش ربح متوقع، نسبة سيولة صحية، مدة تصريف مخزون طبيعية) — كل صيدلية غير سوبرماركت غير مطعم.

### 2.2 Branch (الفرع)
| الحقل | الوصف |
|---|---|
| id, organizationId | ربط بالمؤسسة |
| name | اسم الفرع |
| city / address | الموقع |
| isActive | فعال أو مغلق |

كل شاشات النظام (لوحة القيادة، المبيعات، المخزون...) لازم تدعم فلترة بـ**الفرع** (فرع واحد أو "جميع الفروع" = تجميع) و**التاريخ** (نطاق مخصص أو Presets: اليوم، آخر 7 أيام، الشهر الحالي، مخصص).

### 2.3 User (مستخدم داخل المؤسسة)
أدوار: `OWNER` (صاحب المؤسسة، صلاحية كاملة)، `BRANCH_MANAGER` (صلاحية على فرعه فقط)، `STAFF` (إدخال بيانات فقط).

### 2.4 Category Benchmark Settings (إعدادات المرجعية لكل تصنيف)
جدول يديره الأدمن، يحدد لكل `category`:
- هامش الربح المرجعي المتوقع (Target Margin %)
- نطاق نسبة السيولة الصحية (Current Ratio Range)
- نطاق "أشهر التغطية" الصحي للمخزون (Inventory Coverage Months)
- عدد الأيام لاعتبار الصنف "راكد" (Stagnation Threshold Days)

هذا الجدول هو ما يسمح للسكور إنه يكون عادل بين مؤسسة صيدلية (هامش ربح مرتفع، دوران بطيء) ومؤسسة سوبرماركت (هامش منخفض، دوران سريع).

## 3. الإدخال اليدوي للبيانات

### 3.1 نموذج إدخال يومي (Sales / Profit / Liquidity Entry)
شاشة بسيطة (ويب + جوال) يدخل فيها المستخدم يوميًا أو دوريًا لكل فرع:

| الحقل | النوع | ملاحظة |
|---|---|---|
| الفرع | اختيار | إلزامي |
| التاريخ | تاريخ | افتراضيًا اليوم |
| إجمالي المبيعات | رقم (شيكل) | |
| إجمالي تكلفة البضاعة المباعة (COGS) | رقم | يُستخدم لحساب الربح |
| إجمالي الربح | محسوب تلقائيًا | = المبيعات − COGS (قابل للتعديل اليدوي إن أراد المستخدم إدخاله مباشرة) |
| السيولة المتاحة | رقم | رصيد نقدي + بنكي حالي |
| الذمم المدينة (له عند الغير) | رقم | اختياري |
| الذمم الدائنة / الالتزامات الحالة (عليه) | رقم | اختياري |

**هامش الربح** (محسوب تلقائيًا، كما طلبت):
```
هامش الربح % = (إجمالي الربح ÷ إجمالي المبيعات) × 100
```

يمكن للمستخدم تعديل إدخال يوم سابق (Edit)، والنظام يحتفظ بسجل تاريخي لكل فرع لحساب الاتجاهات (الرسم البياني للمبيعات، % التغير عن أمس/الفترة السابقة).

### 3.2 نموذج إدخال صنف (Item Entry)
فورم بسيط وسلس (خطوة واحدة، حقول قليلة):

| الحقل | النوع |
|---|---|
| اسم الصنف | نص |
| الفرع | اختيار |
| الفئة الفرعية (اختياري: مواد غذائية، أدوية، إلخ) | نص/اختيار |
| سعر التكلفة | رقم |
| سعر البيع | رقم |
| الكمية الحالية | رقم |
| تاريخ آخر بيع | تاريخ (يُحدَّث تلقائيًا مع كل عملية بيع مسجلة، أو يدويًا في MVP) |
| تاريخ انتهاء الصلاحية | تاريخ (اختياري — مهم للصيدليات والمواد الغذائية) |

هامش ربح الصنف يُحسب تلقائيًا وعرض فوري (Live) أثناء الكتابة. عند الحفظ ينضم الصنف لتصنيف الحركة (سريع/متوسط/بطيء/راكد) بناءً على القاعدة في القسم 5.

## 4. مؤشر صحة الأعمال (Business Health Score)

نفس الأبعاد الستة الظاهرة في الراداتشارت الحالي: **المبيعات، الربحية، التسعير، المشتريات، المخزون، السيولة**. كل بُعد سكور من 0–100، والسكور الكلي = متوسط مرجّح.

```
BHS = Σ (sub_score_i × weight_i)     حيث Σ weight_i = 100%
```

الأوزان الافتراضية متساوية (16.7% لكل بُعد) لكن قابلة للتعديل من الأدمن لكل تصنيف نشاط (مثال: للصيدلية وزن المخزون/الصلاحية أعلى؛ للسوبرماركت وزن المبيعات/التسعير أعلى).

### 4.1 سكور المبيعات
مقارنة نمو المبيعات بالفترة السابقة:
```
growth% = (مبيعات الفترة الحالية − مبيعات الفترة السابقة) ÷ مبيعات الفترة السابقة
sales_score = clamp(50 + growth% × 200, 0, 100)
```
(نمو 0% = سكور 50 "متعادل"، نمو +25% أو أكثر = 100، تراجع −25% أو أكثر = 0)

### 4.2 سكور الربحية
مقارنة هامش الربح الفعلي بالهامش المرجعي للتصنيف (من إعدادات Benchmark):
```
profit_score = clamp((هامش الربح الفعلي ÷ الهامش المرجعي) × 100, 0, 100)
```

### 4.3 سكور التسعير
نسبة الأصناف التي هامش ربحها ضمن "نطاق صحي" (ليس منخفض جدًا يخسّر، وليس مرتفع جدًا يفقد المنافسة):
```
pricing_score = (عدد الأصناف ضمن النطاق الصحي ÷ إجمالي عدد الأصناف المسعّرة) × 100
```
النطاق الصحي = [الهامش المرجعي − 5%, الهامش المرجعي + 10%] (قابل للتعديل).

### 4.4 سكور المشتريات
مبني على "أشهر التغطية" — كم شهر يكفي المخزون الحالي عند معدل المبيعات:
```
inventory_coverage_months = قيمة المخزون الحالي ÷ متوسط المبيعات الشهرية
```
إذا كانت القيمة ضمن النطاق الصحي للتصنيف → 100، وكل انحراف (شراء زائد يجمّد سيولة، أو نقص يعرّض لنفاذ المخزون) يُنقص السكور تدريجيًا.

### 4.5 سكور المخزون
باستخدام نفس تصنيف الحركة الظاهر في القسم الدائري الحالي (سريع/متوسط/بطيء/راكد)، بوزن كل فئة حسب قيمتها في المخزون:
```
inventory_score = (قيمة سريع×1.0 + قيمة متوسط×0.6 + قيمة بطيء×0.3 + قيمة راكد×0.0)
                   ÷ إجمالي قيمة المخزون × 100
```

### 4.6 سكور السيولة
باستخدام نسبة التداول (Current Ratio):
```
current_ratio = السيولة المتاحة ÷ الالتزامات الحالة
```
ضمن النطاق الصحي للتصنيف (مثلًا 1.0–2.0) → 100، وينخفض السكور بشكل حاد كلما قلّت النسبة عن 1 (خطر عسر سيولة)، وبشكل أخف إذا ارتفعت كثيرًا (سيولة مجمّدة غير مستثمرة).

### 4.7 تصنيف السكور الكلي
| النطاق | الوصف | اللون |
|---|---|---|
| 81–100 | ممتاز | أخضر |
| 61–80 | جيد | أخضر فاتح |
| 41–60 | مقبول | أصفر |
| 0–40 | ضعيف | أحمر |

## 5. تصنيف حركة المخزون (يُستخدم في القسم 4.5 وفي شاشة المخزون)

| الفئة | القاعدة (افتراضية، قابلة للتعديل لكل تصنيف) |
|---|---|
| سريع الحركة | آخر بيع خلال ≤ 14 يوم |
| متوسط الحركة | آخر بيع بين 15–30 يوم |
| بطيء الحركة | آخر بيع بين 31–60 يوم |
| راكد | آخر بيع منذ أكثر من 60 يوم (أو انتهاء صلاحية قريب < 30 يوم) |

## 6. محرك التوصيات (Rule Engine — بدون ذكاء صناعي)

كل قاعدة تُنتج توصية لها: نوع، أولوية، وقيمة مالية متوقعة (توفير/ربح). الأولوية تُحدَّد آليًا حسب القيمة المالية:

| الأولوية | القيمة المالية المتوقعة |
|---|---|
| عالية | ≥ 50,000 شيكل |
| متوسطة | 15,000 – 49,999 شيكل |
| منخفضة | < 15,000 شيكل |

**القواعد:**

1. **أوقف الشراء (مخزون راكد)** — إذا كان الصنف `راكد` ولم يُطلب منه شراء جديد مؤخرًا → توصية "أوقف شراء [الصنف]"، القيمة المتوقعة = الكمية الحالية × سعر التكلفة (توفير تجميد سيولة).
2. **زد الطلب (فرصة ربح)** — إذا كان الصنف `سريع الحركة` وهامش ربحه أعلى من المرجعي، والكمية المتبقية تكفي أقل من 7 أيام عند معدل البيع الحالي → توصية "زد طلب [الصنف]"، القيمة المتوقعة = متوسط المبيعات اليومية × الهامش × عدد أيام التغطية الإضافية المقترحة.
3. **عدّل السعر** — إذا كان هامش ربح الصنف خارج النطاق الصحي (القسم 4.3) → توصية "عدّل سعر [الصنف]" مع اقتراح سعر جديد يعيده للنطاق، والقيمة المتوقعة = فرق الهامش × الكمية المباعة المتوقعة شهريًا.
4. **حملة ترويجية** — إذا كان الصنف `بطيء` أو `راكد` وقيمته الإجمالية مرتفعة نسبيًا → توصية "أطلق حملة ترويجية" لتسريع التصريف، القيمة المتوقعة = القيمة المقدرة للمخزون المستهدف للتصفية.
5. **تنبيه سيولة** — إذا كانت `current_ratio < 1` → توصية عاجلة بخيارات تحرير سيولة (تصفية راكد، تأجيل مشتريات غير ضرورية).
6. **تنبيه صلاحية** — إذا اقترب تاريخ انتهاء صلاحية صنف (< 30 يوم) بغض النظر عن حركته → توصية "صرّف [الصنف] قبل الانتهاء" (مهم بشكل خاص للصيدليات والمواد الغذائية).

كل التوصيات تظهر في شاشة "التوصيات" مرتبة حسب الأولوية، مع إمكانية "تطبيق" (تعليم كمنفّذة) أو "تجاهل" (مع سبب اختياري لتحسين القواعد لاحقًا).

## 7. شاشات القائمة الجانبية (تصميم مقترح)

### 7.1 الرئيسية
كما في التصميم الحالي: بطاقات المؤشرات، مؤشر صحة الأعمال (راداتشارت)، رسم المبيعات، التوصيات، المخزون، السيولة، أصناف تحتاج انتباه.

### 7.2 المبيعات
- رسم بياني للمبيعات عبر الزمن (يومي/أسبوعي/شهري) قابل للفلترة بالفرع والتاريخ.
- جدول مقارنة أداء الفروع (لو أكثر من فرع) — الأعلى/الأدنى مبيعات.
- مقارنة بالفترة السابقة ونفس الفترة من الشهر/السنة الماضية.

### 7.3 المخزون
- تبويبات: الكل / سريع / متوسط / بطيء / راكد.
- جدول كامل بالأصناف: الاسم، الكمية، القيمة، تاريخ آخر بيع، الحالة، تاريخ الانتهاء (إن وجد).
- زر "إضافة صنف" يفتح فورم القسم 3.2.
- تنبيه صلاحية قريبة كصف مميز بلون أحمر/برتقالي.

### 7.4 المشتريات
- سجل عمليات الشراء (المورد، الصنف، الكمية، التكلفة، التاريخ، الفرع).
- مؤشر "أشهر التغطية" لكل فئة أصناف.
- ربط مباشر بتوصيات "زد الطلب" و"أوقف الشراء".

### 7.5 الربحية
- هامش الربح عبر الزمن (رسم بياني).
- تحليل الربحية حسب الفرع وحسب الصنف (الأعلى ربحية / الأقل ربحية).
- مقارنة بالهامش المرجعي للتصنيف.

### 7.6 السيولة
- نسبة التداول عبر الزمن.
- تفصيل: سيولة متاحة، ذمم مدينة، ذمم دائنة، رأس المال العامل.
- توقّع تحرير السيولة المتوقع من تنفيذ التوصيات النشطة (كما في الشريط السفلي بالتصميم الحالي).

### 7.7 التسعير
- جدول الأصناف مع هامش الربح لكل صنف ومؤشر لونی (ضمن/خارج النطاق الصحي).
- أداة محاكاة: "لو غيّرت سعر الصنف X إلى كذا، الهامش يصير كذا والأثر المتوقع على الربح الشهري كذا".

### 7.8 التقارير
- تقارير جاهزة قابلة للتصدير (PDF/Excel): تقرير شهري شامل، تقرير مخزون راكد، تقرير أداء فروع.
- جدولة تقرير دوري يُرسل بالبريد (Phase 2).

### 7.9 التنبيهات
- سجل كل التنبيهات (صلاحية، سيولة، ركود، فرص) مع حالة (جديد/مقروء/تم التعامل معه).
- إعدادات: تفعيل/تعطيل أنواع تنبيهات معينة، حد الأيام لاعتبار الصنف راكد (تخصيص فوق الإعداد الافتراضي).

### 7.10 الموردون
- قائمة الموردين وبيانات التواصل والأصناف المرتبطة بكل مورد.
- سجل طلبات الشراء الجماعي (Group Orders) التي شارك بها هذا المستخدم عبر الأدمن — الحالة، الكمية، السعر بالجملة مقابل السعر الفردي، التوفير المحقق.

### 7.11 الإعدادات
- بيانات المؤسسة والتصنيف والفروع (إضافة/تعديل فرع).
- إدارة المستخدمين والأدوار.
- تخصيص عتبات القواعد (أيام الركود، نطاق الهامش الصحي) ضمن الحدود التي يسمح بها الأدمن.

## 8. لوحة تحكم الأدمن

نفس هيكلية لوحة المستخدم لكن على مستوى المنصة كاملة، مع إضافتين جوهريتين تحقق الربح للمنصة:

### 8.1 نظرة عامة على المنصة
- عدد المؤسسات النشطة، موزّعة حسب التصنيف.
- متوسط سكور صحة الأعمال عبر المنصة (Benchmark حقيقي).
- خريطة/جدول لكل المؤسسات مع سكورها وآخر نشاط.

### 8.2 الأصناف المطلوب تصريفها (تجميع البيانات عبر المستخدمين)
- تجميع كل الأصناف `راكدة` أو قريبة الصلاحية عبر كل المؤسسات (مطابقة حسب اسم الصنف/الفئة).
- عرض: الصنف، عدد المؤسسات التي تملكه راكدًا، إجمالي الكمية، القيمة الإجمالية، أفضل فرص المطابقة (مؤسسة عندها فائض ↔ مؤسسة أخرى بحاجة له بسعر أقل من السوق).
- نموذج الربح: المنصة (أو طرف وسيط) تشتري الفائض بسعر منخفض من المؤسسة صاحبة الركود، وتبيعه بسعر أقل من السوق (لكن أعلى من سعر الشراء) لمؤسسة أخرى محتاجة → هامش ربح للمنصة + تقليل هدر لصاحب الركود.

### 8.3 الطلبات الجماعية من الموردين (Group Purchasing)
- تجميع طلبات الشراء المتكررة لنفس الصنف عبر عدة مؤسسات صغيرة خلال نافذة زمنية معينة.
- عند الوصول لحد أدنى من الكمية الإجمالية → المنصة تفاوض المورد على سعر جملة أفضل من سعر الشراء الفردي.
- المنصة تبيع للمؤسسات المشاركة بسعر بين سعر الجملة وسعر السوق الفردي → هامش ربح للمنصة + توفير للمؤسسات المشاركة.
- شاشة إدارة: حالة كل طلب جماعي (تجميع/تم التفاوض/تم التوزيع)، عدد المشاركين، الكمية الإجمالية، هامش ربح المنصة المحقق.

### 8.4 إعدادات النظام
- تعديل جداول Benchmark لكل تصنيف نشاط (هامش مرجعي، نطاق سيولة صحي، عتبة الركود).
- إدارة الأوزان الافتراضية لسكور صحة الأعمال لكل تصنيف.

| Backend | Spring Boot (Java 21)، معمارية طبقية Controller → Service → Repository، Spring Security + JWT للمصادقة والأدوار |
| قاعدة البيانات | PostgreSQL، Flyway لإدارة الـ migrations |
| المهام الدورية | Spring Scheduler لإعادة حساب السكور والتصنيفات (المخزون الراكد، التنبيهات) يوميًا |
| النشر | REST API عبر HTTPS، Frontend كتطبيق SPA منفصل يستهلك الـ API |

### 9.2 مبدأ الاستجابة (Responsive / Mobile)
- تصميم Mobile-first للفورمات الحرجة (إدخال صنف، إدخال يومي) — حقول كبيرة، لوحة مفاتيح رقمية للحقول المالية، خطوة واحدة بلا تمرير أفقي.
- لوحة القيادة: على الجوال تتحول البطاقات العلوية إلى Carousel أفقي قابل للتمرير بدل شبكة 5 أعمدة، والراداتشارت والرسم البياني يتكدسان عموديًا.
- القائمة الجانبية تتحول لقائمة سفلية (Bottom Nav) أو Drawer قابل للسحب على الشاشات الصغيرة.
- الجداول (المخزون، الأصناف) تتحول لبطاقات (Cards) بدل صفوف جدول على الشاشات الصغيرة جدًا.

## 10. خارطة الطريق (Phasing)

**المرحلة 1 — MVP (هذه الخطة):**
- تسجيل الدخول، إعداد المؤسسة/الفروع/التصنيف.
- إدخال يدوي يومي (مبيعات/ربح/سيولة) + إدخال أصناف.
- حساب مؤشر صحة الأعمال بالقواعد الست.
- محرك توصيات قائم على قواعد ثابتة.
- شاشات: الرئيسية، المبيعات، المخزون، المشتريات، الربحية، السيولة، التسعير، التنبيهات، الإعدادات.
- لوحة أدمن: نظرة عامة + تجميع الأصناف الراكدة (عرض فقط، بدون أتمتة مطابقة).

**المرحلة 2:**
- أتمتة مطابقة تصريف الراكد بين المؤسسات (Clearance Matching Engine).
- الطلبات الجماعية من الموردين بشكل كامل (تجميع تلقائي + تفاوض + توزيع).
- تقارير مجدولة عبر البريد، تصدير PDF/Excel.
- ربط نقاط البيع (POS) لسحب المبيعات تلقائيًا بدل الإدخال اليدوي.

**المرحلة 3:**
- إضافة الذكاء الاصطناعي (شات بوت "المدير الذكي" + توصيات تنبؤية بدل القواعد الثابتة).
- مؤشرات قطاعية معيارية (Industry Benchmarks) مبنية على بيانات حقيقية متراكمة من كل المؤسسات على المنصة.
